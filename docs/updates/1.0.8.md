# 轻账本 1.0.8：减少付款通知附带数字时的漏记

更新日期：2026-11-02，北京时间

## 本次变化

- 微信或支付宝通知开头明确描述已完成的一笔付款，或者明确写出“一笔……元的支出”时，若后文还有权益等金额而不能按原规则确定唯一金额，优先取第一笔非优惠金额记账。
- 仍过滤日报、月报、待支付、失败、纯促销，以及明确提到第二笔付款的通知；不生成零元账单。
- 自动记账诊断把系统未说明具体原因的后台进程结束显示得更清楚，方便区分识别失败与监听中断。

## 使用方法

同签名覆盖安装即可保留现有账单和通知读取权限。自动记账后在首页“待确认金额”核对金额；如有误识别，可修改或删除。若曾漏记的通知已从系统通知栏消失，需按需手动补录。

## 验证结果

- 使用虚构文案运行通知解析定向测试：21 项通过，覆盖开头完成付款后附加金额、支付宝单笔支出后附加金额、纯优惠、明确第二笔付款和付款处理中等情况；未进行新的真实付款。
- `assembleRelease` 构建成功；APK 为 versionCode34 / versionName1.0.8、minSdk26、targetSdk35，v2 签名有效，证书与 1.0.7 相同。
- OPPO PFEM10 / ColorOS 16 从 1.0.7 同签名覆盖安装成功；系统报告 versionCode34，通知读取权限仍启用，监听服务和后台保护服务均已连接。该检查只证明升级当时的状态，不能证明长期不会断联。
- 手机近期诊断曾显示微信与支付宝通知因“缺少金额或金额冲突”被跳过，也记录到系统多次结束后台进程。具体漏记通知已消失，无法判定每笔是金额识别失败还是监听未收到。

## 已知限制

- 对开头明确是完成付款的通知采用第一笔金额可能误认个别复杂文案；建议在“待确认金额”核对。通知没有金额、没有被系统投递，或已消失时不能自动补记。
- ColorOS 16 曾多次结束监听进程，当前代码无法保证系统始终投递通知。此次未做新的真实微信或支付宝付款测试，也未在荣耀 X10 Max / HarmonyOS 3 验证。
