# 轻账本 0.10.1：后台监听与页面分离

更新日期：2026-10-12，北京时间

## 本次变化

- 将所有页面放入独立的页面进程，通知监听、后台保护及恢复任务保留在原来的默认进程。页面的启动、重建和退出不再共用监听的内存状态，减少页面进程退出时连带中断监听的机会。
- 保留原通知监听组件和授权入口。页面通过应用内私有接口读取实际连接、保护状态和诊断结果，不直接读取另一个进程的静态变量或偏好缓存。
- 页面启动检查与后台保护启动请求合并处理，避免首次检查尚未完成时遗漏保护启动。后台状态长时间不可读会显示“检查后台”，不会继续显示缓存中的“已连接”。
- 后台接口在工作线程请求，新增账单等待最近监听支付方式有时限；手动选择不会被迟到的默认值覆盖。编辑历史账单、截图确认仍使用各自方式。
- 启用Room跨实例失效通知，后台保存、修改或删除账单后，已打开的页面能收到数据变化；保留通知去重与原数据结构。
- 后台保护开关在读取状态和提交变更时暂时不可操作，避免使用尚未更新的状态反复切换。

## 使用方法

1. 覆盖安装并打开一次应用，在“我的 → 自动记账”核对通知读取与后台保护。
2. 从主页退出后可继续由后台监听通知。若手机系统仍清理应用，可锁定最近任务中的轻账本卡片，并按“允许后台运行”指引检查系统设置。
3. 页面显示“后台状态暂不可读”时，点“检查后台”查看状态及系统后台设置；它表示暂时无法获取状态，不等同于已确认监听断开。
4. 手动新增仍优先使用最近识别的微信或支付宝方式，可以直接改选。没有可靠金额的通知继续跳过，不生成零元账单。

- API26/29/35验证页面进程、默认监听进程、组件名称和授权权限；私有接口状态、正常连接修复不重绑、保护开启/关闭、拒绝未知请求、启动检查期间保留保护启动请求通过。
- 模拟跨进程调用在工作线程执行，状态失效或读取失败不沿用已连接缓存；持续不可读后出现后台检查提示。慢接口等待有时限，录入页从后台取得方式，迟到结果不覆盖手动选择。
- API29/35使用两个同名数据库实例和Room实际本地Binder，验证后台新增、改金额/备注、删除后另一实例的LiveData更新；页面数据库关闭再打开仍保留账单；并发重复通知仅保存一笔。
- 原有通知解析/去重、无可靠金额跳过、监听和保护组件生命周期、恢复节流、录入/搜索/统计/分类、迁移、备份与分页检查继续通过。测试服务绑定补上Room的本地Binder，以避免Robolectric默认空绑定影响回归。

- 以上是电脑端组件、接口和数据库模拟检查；Robolectric没有真正创建两个Android进程，不模拟ColorOS进程清理、系统冻结或真实支付。此次没有操作或安装手机，本版真机验收尚未完成。

进程安排与组件生命周期依据[Android进程说明](https://developer.android.com/guide/components/processes-and-threads)，数据库同步使用[Room多实例失效通知](https://developer.android.com/reference/androidx/room/RoomDatabase.Builder#enableMultiInstanceInvalidation())；截图识别的初始化入口按[ML Kit初始化说明](https://developers.google.com/android/reference/com/google/mlkit/common/MlKit)保留在页面所在进程。

## 已知限制

- 此前在ColorOS16 / Android16真机排查中，系统记录出现最近任务划掉清理与后台清理，监听会在进程恢复后重新绑定；另观察到系统冻结与通知处理延迟发生在同一时段。这些是旧版现场观察，不是本版验收结论。
- 本版尚未做真机安装、最近任务划掉、长时间锁屏、真实支付或耗电验收；用户暂时不方便使用手机，本轮先完成代码与电脑端验证。HONOR X10 Max / HarmonyOS3.0也未进行本版真机验证。
- 系统仍可结束整个应用、冻结整个应用的进程或延迟任务。分离页面不能绕过系统清理，不能保证持续监听；强行停止后需重新打开应用。
- 恢复时只能回读仍保留的通知；没有产生或已经清除的通知不能找回。金额不可靠时不会自动建账。
- 进程分离可能增加内存使用，本版未测量真实手机耗电和内存变化。
